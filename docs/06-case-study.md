# روایت اجرای واقعی — از ایده تا MVP موفق

[خانه](../README.md) | [نقشه دانش](00-knowledge-map.md) | [دفترچه خطاها](03-troubleshooting.md)

این صفحه شرح یک اجرای واقعی با **اطلاعات هویتی و نشانی سرور حذف‌شده** است. هدف، ثبت تصمیم‌ها و اشتباه‌هاست تا خواننده بتواند دلیل هر مرحله را بفهمد. دستورهای عمومی و به‌روزتر در [راهنمای نصب](02-step-by-step.md) قرار دارند.

## مسئله اولیه

ابتدا درباره ریسک تشخیص موقعیت در سرویس‌های آنلاین و نقش IP، Timezone، Browser Fingerprint و Geolocation پرسش مطرح شد. چند تست مرورگر نشان داد که **مقدار خروجی یک API فقط همان API را توصیف می‌کند**: مثلاً IP، Timezone و Geolocation ظاهراً با یک کشور سازگار بودند، اما این موضوع نه موقعیت فیزیکی را اثبات می‌کند و نه وضعیت حساب نزد ارائه‌دهنده مدل را.

برای محیط توسعه، ایده متفاوتی مطرح شد: به‌جای ساخت Proxy اختصاصیِ پیام‌های افزونه، اجرای Claude Code و ابزارها روی VPS باشد؛ VS Code لپ‌تاپ فقط به محیط Remote متصل شود. این انتخاب معماری برای **دورکاری، مدیریت مستقل فایل و کاهش پیچیدگی** است، نه تضمین جلوگیری از بن شدن.

## سه نقطه عطف

### ۱. حذف Bridge اختصاصی

ابتدا فکر می‌کردیم برای رساندن گفتگوی افزونه به CLI روی VPS باید سرویس WebSocket یا HTTPS بسازیم. اما وقتی پروژه و خود افزونه روی Remote SSH اجرا می‌شوند، VS Code و VS Code Server ارتباط لازم را برقرار می‌کنند. حذف Bridge باعث شد نیازی به مدیریت جداگانه Session Streaming، Protocol و مجوزهای ابزار نباشد.

### ۲. تبدیل «به‌یادآوردن دستور توسط ایجنت» به Hook

به‌جای افزودن توضیحات طولانی در ابتدای هر پرامپت، قرارداد کوتاه را در CLAUDE.md قرار دادیم و ثبت واقعی رویدادها را به Hook سپردیم. در طراحی آزمایشی، SessionStart، UserPromptSubmit و Stop ثبت می‌شوند؛ در نسخه نمونه عمومی، Git Checkpoint نیز به Stop اضافه شده است.

این روش **قطعی بودن اجرای Hook در صورت فراخوانی رویداد** را بهتر از درخواست متنی تضمین می‌کند، اما از کرش، قطع فرایند یا عدم بارگذاری Hook در Harnessهای متفاوت مصون نیست.

### ۳. Mirror یک‌طرفه بدون پورت عمومی جدید

Syncthing روی هر دو دستگاه فقط به 127.0.0.1:22000 گوش می‌دهد و SSH با Forward و Reverse به 22001 متصلش می‌کند. پنل سرور با Local Forward به 8385 روی Windows دیده می‌شود. VPS نسخه اصلی را نگه می‌دارد و Windows نسخه دریافت‌شده را. فایل .git عمداً Sync نشده است.

## مهم‌ترین خطای واقعی و علت ریشه‌ای

در Task خودکار Windows لاگ به‌طور مکرر نشان می‌داد:

~~~text
ssh: Could not resolve hostname claude-vps: No such host is known.
~~~

این **خطای DNS سرور یا خرابی Syncthing نبود**. نام claude-vps یک Alias محلی بود که اسکریپت SSH در آن اجرا نمی‌توانست از Config بازیابی کند. در اجرای واقعی، با مشخص کردن مقصد واقعی SSH و کلید به‌صورت صریح، تونل دوباره برقرار شد.

در نمونه منتشرشده، به‌جای ثبت IP شخصی، **HostName و IdentityFile در %USERPROFILE%\.ssh\config** و اجرای ssh با **-F** توصیه می‌شود. این روش عمومی‌تر است و اطلاعات سرور را از کد عمومی جدا نگه می‌دارد.

## چیزهایی که عمداً حذف شد

- Proxy اختصاصی برای API یا جعل محل حضور فیزیکی کاربر
- همگام‌سازی مستقیم پوشه .git
- Git Push خودکار یا انتشار بدون مرور انسان
- Git Bundle و تاریخچه کامل روی لپ‌تاپ (پیشنهاد شد اما اجرا نشد)
- Docker، Redis، Queue، Agent Orchestration یا داشبورد جدید
- هرگونه تغییر در Nginx یا سرویس‌های موجود VPS

## تفاوت کد عمومی با اجرای شخصی

- اصل انتخاب معماری، گام‌های نصب، خطاها و موفقیت‌های اعلام‌شده بر اساس مسیر واقعی هستند.
- فایل نمونه session.py یک **بازسازی آموزشی** است که به‌طور عمدی فیلتر Path و Branch محافظه‌کارانه دارد؛ ادعا نمی‌شود بایت‌به‌بایت همان فایل خصوصی روی VPS باشد.
- اسکریپت PowerShell نمونه از تجربه مشکل DNS/Host Alias آموخته و **مسیر Config صریح و Log قبل از اتصال** دارد.
- هیچ Secret، کلید ورود، IP واقعی، نام ماشین خصوصی یا متن گفتگوهای شخصی در ریپو قرار نگرفته است.
- قبل از استفاده عمومی کد باید در محیط مستقل تست و بازبینی شود؛ موفقیت آزمایش صاحب این روایت به‌تنهایی گواه تست همه سناریوها نیست.

## نتیجه عملی

**MVP تأییدشده:** Remote Agent روی VPS، Workspace و Hookهای پروژه، Git Checkpoint، Mirror یک‌طرفه Syncthing و SSH Tunnel با بازیابی خودکار. قابلیت‌های اختیاری و توسعه‌های بعدی عمداً خارج از محدوده باقی مانده‌اند.

منابع رسمی: [Remote SSH](https://code.visualstudio.com/docs/remote/ssh)، [Claude Hooks](https://code.claude.com/docs/en/hooks)، [Syncthing Tunneling](https://docs.syncthing.net/users/tunneling.html).
