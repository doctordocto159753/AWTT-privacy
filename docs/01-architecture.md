# معماری و تصمیم‌های طراحی

[خانه](../README.md) · [نقشه دانش](00-knowledge-map.md)

## مسئله و هدف

می‌خواهیم در لپ‌تاپ با تجربه عادی VS Code کار کنیم، اما پروژه‌ها، اجرای ابزارهای Agent و تغییر فایل‌ها روی Linux VPS انجام شود. نسخه قابل مشاهده و قابل استفاده فایل‌ها به‌طور خودکار روی لپ‌تاپ ذخیره شود؛ در صورت آفلاین بودن لپ‌تاپ تغییرات بعداً دریافت شوند.

**هدف:** استقلال محل نگهداری پروژه، کاهش نیاز به اجرای ابزار روی لپ‌تاپ، بازتولیدپذیری کار، کاهش باز کردن پورت عمومی و داشتن یک Mirror. **هدف نیست:** تضمین ناشناس‌ماندن، گریز از تشخیص موقعیت یا دورزدن مقررات دسترسی یک سرویس.

## تصمیم‌های قطعی MVP

| تصمیم | دلیل |
|---|---|
| VS Code Remote SSH به‌جای Bridge اختصاصی | رابط و مدیریت ابزار آماده است؛ بدون نوشتن پروتکل جدید |
| کاربر اختصاصی بدون دسترسی sudo | کاهش سطح آسیب در صورت خطای Agent |
| یک Workspace اصلی روی VPS | جلوگیری از دو نسخه هم‌زمان و متعارض |
| \`CLAUDE.md\` برای قرارداد کوتاه، Hook برای اجرای قطعی | اجرای عملیات حساس وابسته به حافظه مدل نباشد |
| \`SessionStart\` / \`UserPromptSubmit\` / \`Stop\` | ثبت آغاز، هر نوبت و پایان پاسخ |
| Checkpoint فقط روی \`agent/*\` | جلوگیری از Commit ناخواسته در main و تغییرات کاربر |
| عدم \`git push\` خودکار | کنترل انتشار در اختیار انسان |
| Syncthing Send Only → Receive Only | Mirror یک‌طرفه؛ عدم ارسال تغییرات لپ‌تاپ به VPS |
| \`.git\` در Ignore همگام‌سازی | جلوگیری از خرابی مخزن در فایل‌به‌فایل Sync |
| SSH Tunnel با \`-L\` و \`-R\` روی \`127.0.0.1\` | بدون نیاز به باز کردن پورت عمومی جدید |
| انتقال تاریخچه Git با Bundle | **در این MVP فعال نشده**؛ عمداً خارج از دامنه فعلی |

## مرزهای اعتماد

\`\`\`text
[Windows Laptop]
  VS Code (رابط)
  SSH private key — هرگز روی VPS یا GitHub بارگذاری نشود
  Local Syncthing + Mirror
        │ SSH encrypted + authenticated
        ▼
[VPS: unprivileged account]
  VS Code Server / Claude CLI
  Projects, tests, artifacts
  Session Hooks / Git
  Syncthing only on 127.0.0.1
        │
        ▼
[External AI service]
  Requests are processed by provider; VPS location ≠ physical location of user
\`\`\`

در این مدل، **کد و ابزارها روی VPS اجرا می‌شوند**. خود فایل‌های پروژه ممکن است مطابق تصمیم ایجنت و مجوزهای ابزار به سرویس مدل ارسال شوند؛ این سیستم به‌تنهایی حریم خصوصی محتوای فرستاده‌شده به مدل را تضمین نمی‌کند.

## چرخه یک نوبت

۱. کاربر در VS Code متصل به SSH درخواست می‌نویسد.
۲. \`UserPromptSubmit\` رویداد را ثبت می‌کند و فقط Hash پرامپت را نگه می‌دارد.
۳. ایجنت در پروژه VPS فایل می‌سازد/تغییر می‌دهد و تست اجرا می‌کند.
۴. هنگام \`Stop\` اسکریپت وضعیت Git را می‌خواند؛ اگر شرط‌ها برقرار باشند، فقط فایل‌های مجاز را Commit می‌کند.
۵. فایل \`manifest.json\` آخرین وضعیت را نشان می‌دهد. **وجود آن به معنی رسیدن فایل به لپ‌تاپ نیست.**
۶. Syncthing تغییرات را روی ویندوز تکثیر می‌کند؛ دستگاه گیرنده باید Connected/Up to Date شود.

## تفاوت سه وضعیت

- **Saved on VPS:** فایل واقعاً در پوشه پروژه وجود دارد.
- **Checkpointed:** تغییر در Git Commit ثبت شده است؛ ممکن است برخی فایل‌ها به‌دلیل سیاست امنیتی مستثنا باشند.
- **Synced to laptop:** Syncthing تأیید می‌کند نسخه مقصد به‌روز است. Hook بدون دریافت تأیید از مقصد نباید ادعای این وضعیت را بکند.

## فایل‌ها و پوشه‌ها

\`\`\`text
/home/claude-runner/claude-workspaces/
  projects/<project>/
    .git/                  # فقط VPS
    .claude/hooks/         # کد اجرایی، پیش از استفاده باید بررسی شود
    .sessions/<session-id>/
      events.jsonl
      manifest.json
    src/ tests/ docs/ artifacts/
  standalone-sessions/<session-id>/   # برای کارهای غیرپروژه‌ای، در صورت نیاز

Windows mirror:
  D:\\ClaudeMirror\\projects\\<project>\\...
\`\`\`

این مسیرها نمونه‌اند؛ سایر کاربران باید آن‌ها را با محیط خود تطبیق دهند. ریشه همگام‌سازی نباید \`/home\` یا \`/\` باشد.

## خطرها و محدودیت‌های مهم

- **Hook زمان‌بندی تضمینی تکمیل کار نیست:** \`Stop\` ممکن است هنگام قطع فرایند یا کرش اجرا نشود.
- **Git Commit، بکاپ امنیتی نیست:** نسخه‌های Commitنشده، داده‌های Ignoreشده و خرابی دیسک همچنان مسئله‌اند.
- **Syncthing نسخه‌ای از فایل را کپی می‌کند، نه تراکنش اتمیک پروژه:** هنگام کار ممکن است گیرنده فایل نیمه‌تمام دریافت کند. Manifest و Checkpoint علامت پایان نوبت‌اند.
- **Receive Only آرشیو تغییرناپذیر نیست:** حذف روی سرور می‌تواند به لپ‌تاپ منتقل شود. Versioning محلی فعال کنید.
- **Auto Commit کار اشتباه را صحیح نمی‌کند:** تست، Code Review و تأیید انسانی همچنان ضروری‌اند.
- **دستگاه گیرنده و سرور را به‌عنوان محیط‌های قابل اعتماد پیکربندی کنید:** SSH، Syncthing و افزونه‌ها توان خواندن/نوشتن اطلاعات قابل دسترس حساب خود را دارند.
- **پورت 8385 فقط داشبورد تونل‌شده است؛** اگر اتصال SSH قطع شود، این آدرس هم از دسترس خارج می‌شود، حتی اگر Syncthing روی VPS سالم باشد.
