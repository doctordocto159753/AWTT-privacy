# امنیت، حریم خصوصی و محدودیت‌های ادعا

[خانه](../README.md) · [معماری](01-architecture.md)

## این پروژه چه چیزی را محافظت می‌کند؟

- کپی محلی فایل‌ها با کنترل کاربر؛ امکان کار روی یک VPS بدون انتقال دستی فایل پس از هر گفتگو.
- جداسازی ایجنت در کاربر Linux محدود، به‌جای اجرای Agent با root.
- کاهش سطح شبکه با قراردادن Syncthing و پنل آن روی loopback و عبور از تونل SSH.
- ثبت حداقلی متادیتای نشست بدون نگهداری متن کامل پرامپت در مثال Hook.
- کنترل تغییرات ثبت‌شده در Git روی شاخه‌های مخصوص Agent.

## این پروژه چه چیزی را محافظت نمی‌کند؟

- موقعیت فیزیکی واقعی کاربر را اثباتاً مخفی نمی‌کند.
- به ناشناس‌ماندن در برابر ارائه‌دهنده مدل یا جلوگیری از تعلیق حساب ضمانت نمی‌دهد.
- جلوی ارسال Context به سرویس مدل، تله‌متری ابزارها یا دسترسی ارائه‌دهنده VPS به زیرساخت خود را لزوماً نمی‌گیرد.
- تضمین نمی‌کند هیچ Secret در Git Commit ثبت نشود. فیلتر نام فایل جایگزین Secret Scanner و Code Review نیست.
- کپی Receive Only را به بکاپ آف‌سایتِ ضدحذف تبدیل نمی‌کند.

## مقررات جغرافیایی (ویژه Claude)

در تاریخ تدوین این راهنما، [Anthropic Supported Regions Policy](https://www.anthropic.com/legal/supported-regions) مقرر می‌کند دسترسی به خدمات فقط در مناطق پشتیبانی‌شده مجاز است و **حضور فیزیکی در منطقه پشتیبانی‌نشده** مستقل از محل سرور، IP خروجی یا تابعیت می‌تواند مشمول محدودیت شود. این ریپو آموزش توسعه ریموت است؛ برای استفاده از هر سرویس به شرایط و مجوز آن پایبند باشید.

**تست Fingerprint، WebRTC و GeoSpoof** در بهترین حالت نشان می‌دهد یک صفحه وب در آن لحظه چه داده‌ای دریافت کرده است؛ هیچ‌کدام آزمون رسمی پذیرش حساب نزد Anthropic نیستند. دستورالعملی برای فریب سامانه‌های نظارت ارائه نمی‌کنیم.

## کارهایی که قبل از انتشار پروژه خود انجام دهید

۱. هرگز `.ssh`، `.claude.json`، Credentialهای SDK، فایل‌های Token، کلیدهای VPS، `.env` و تراکنش‌ها/گفتگوهای خصوصی را در Public Repo قرار ندهید.
۲. قبل از روشن کردن Auto Commit، مخزن آزمایشی و لیست مجاز مسیرها را بازبینی کنید. مسیر `artifacts/` ممکن است حاوی داده خصوصی باشد.
۳. برای هر مخزن `git status` و تاریخچه را از نظر اسرار بررسی کنید. حذف فایل از Git Working Tree، Secret را از تاریخچه حذف نمی‌کند.
۴. Config داخلی Syncthing شامل Identity Keys است؛ هیچ‌گاه `~/.local/state/syncthing` را Sync عمومی یا Commit نکنید.
۵. سرویس‌ها را تحت کاربر بدون sudo اجرا کنید؛ برای SSH فقط کلید عمومی را روی سرور قرار دهید، کلید خصوصی روی لپ‌تاپ بماند.
۶. Loopback را با `ss -ltn` بررسی کنید: `127.0.0.1:8384` و `127.0.0.1:22000`. اگر روی `0.0.0.0` هستند، قبل از ادامه اصلاح کنید.
۷. روی لپ‌تاپ Versioning Syncthing را فعال کنید و بکاپ مستقل خارج از مسیر Sync داشته باشید.

## تنظیمات نمونه برای Sync و Git

- `examples/sync/.stignore.example`: الگوهای قابل کپی به ریشه پوشه **Syncthing** (فایل واقعی باید `.stignore` نام داشته باشد).
- `examples/project-template/.gitignore`: فایل‌هایی که نباید به تاریخچه Git وارد شوند.
- `session.py`: فقط Pathهای امنِ صریح را Stage می‌کند، نه کل مخزن؛ اما محتوای فایل را برای Secret اسکن نمی‌کند.

**هشدار عملی:** فایل `.stignore` خودش بین دستگاه‌ها Sync نمی‌شود؛ باید سیاست‌ها را از سمت مبدأ تنظیم کنید. `.git` را در Syncthing Ignore کنید و از کپی فایل‌به‌فایل مخزن Git در حال استفاده بپرهیزید.

## مرزبندی حقوقی و اعتماد

این راهنما درباره طراحی سیستم است و مشاوره حقوقی محسوب نمی‌شود. IP خروجی سرور ممکن است یک IP دیتاسنتری و قابل طبقه‌بندی باشد. انتقال CLI به VPS، جابه‌جایی فیزیکی کاربر نیست. امنیت نسبی است؛ تست اتصال و مرور مستندات رسمی برای هر نسخه الزامی است.
